## push-gate переписан на детерминированный гейт + команда разработки на Agent Teams (2026-08-31)

**Проблема.** `.claude/workflows/push-gate-pipeline.js` на каждой итерации запускал до 9
агентов параллельно (code/security-ревью, affected-тесты, автогенерация недостающих тестов,
3 глубоких ревьюера, test-quality-verifier, fixer) и крутил цикл до 15 итераций с
**автономным фиксером**, который сам правил код и коммитил. На бумаге «ограничено», на
практике — нет. Реальный прогон: 4 коммита `fix: address push-gate findings (iteration 1-4)`,
фиксер трогал `main.ts` в итерациях 1, 2 и 4 (осцилляция между правками), автономно добавил
Prisma-миграцию и throttler-guard, так и не сошёлся, агенты зависли и съели весь контекст —
сессию пришлось убить вручную.

**Решение — гейт стал детерминированным, предсказуемым и только-отчётным:**

- **Удалён** `.claude/workflows/push-gate-pipeline.js` (и каталог `workflows/`). Нет цикла
  автопочинки, нет автономных коммитов, нет спавна множества агентов, нет автогенерации
  тестов.
- **Новый** `.claude/hooks/quality-checks.sh` — один полный проход, никогда не обрывается на
  первой красной: `pnpm lint` · affected `type-check` · affected `test` (turbo
  `--filter="...[<base>]"`, синтаксис сверен с turbo docs) · affected `build` · скан
  секретов по добавленным строкам диапазона (regex, без внешних зависимостей; `.env.example`
  и `*.md` исключены). Вывод — `CHECK <name> PASS/FAIL` + хвосты логов красных + `GATE
  PASS/FAIL`.
- **Переписан** `skills/push-gate/SKILL.md`: диапазон → `quality-checks.sh` → ОДИН фоновый
  advisory-субагент `code-reviewer` (без имени — чтобы при включённых Agent Teams остался
  субагентом) → единый подробный отчёт человеку → при `GATE PASS` и без `high`-находок:
  doc-sync + расписка + `git push`; иначе — стоп, находки чиним вместе с пользователем
  обычными Edit/Bash, затем повторный `/push-gate`. Docs-only быстрый путь и механизм
  хэш-расписки сохранены.
- **Новый** `agents/code-reviewer.md` — лёгкое diff-scoped ревью (корректность + явная
  безопасность + конвенции), `maxTurns: 12`, только отчёт по схеме, ≤10 находок.
- `hooks/push-gate.sh`: commit-гейт теперь показывает хвост `pnpm lint` в отказе; текст
  push-отказа переписан под новый гейт. Механизм расписки не тронут.

**Команда разработки — на экспериментальных Agent Teams:**

- `settings.json` → `env.CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. Файла конфигурации команды
  нет (`~/.claude/teams/session-*/` генерируется автоматически); роли — субагент-определения
  в `agents/`.
- **Новые** `agents/backend-dev.md`, `frontend-dev.md`, `test-engineer.md` — разработчики-
  тиммейты по паттернам проекта (`tools: Read, Edit, Write, Bash, Grep, Glob`, `maxTurns: 40`).
  Каждый владеет только закреплёнными за ним файлами.
- **Новый** `skills/feature/SKILL.md` (`/feature <описание>`) — плейбук ведущего (tech-lead =
  основная сессия): план с закреплением файлов (двое тиммейтов не трогают один файл) → спавн
  тиммейтов → координация → ревьюеры-субагенты по областям → `/push-gate`.
- **Ревьюеры** (`security/backend/frontend-reviewer.md`): убраны упоминания удалённого
  workflow, добавлены `model: sonnet` + `maxTurns: 15`. Теперь это роли команды — их
  запускает ведущий субагентами (без имени) по затронутым областям, а не автоматический
  конвейер. `frontend-reviewer` — убраны браузерные `mcp__claude-in-chrome__*` из `tools`
  (риск зависания), ревью только по исходникам. `security-reviewer` — шаг Semgrep обёрнут в
  `timeout 120`.

Документация синхронизирована: `.claude/README.md` (полностью переписан под две части —
гейт и команда), `CLAUDE.md` (секция про push + новая секция про команду), корневой
`README.md`.

## Claude Code не читает секреты: permissions.deny на .env (2026-08-31)

Отдельного `.claudeignore`-файла в Claude Code нет, а прежний `ignorePatterns` объявлен
устаревшим — официальный механизм «спрятать от Claude» это `permissions.deny` с `Read(...)`-
правилами (gitignore-синтаксис) в `.claude/settings.json`. Добавлено:

```json
"permissions": { "deny": ["Read(**/.env)", "Read(**/.env.local)", "Read(**/.env.*.local)"] }
```

- Зеркалит `.gitignore` этого репозитория (те же три паттерна) — консистентность как принцип.
- Блокирует и Read/Edit/Write, и распознаваемые файловые команды в Bash (`cat`/`head`/`tail`/
  `sed`), плюс исключает файлы из поиска и file-discovery. `grep`/`awk` и произвольные
  подпроцессы (`node`, `pnpm`, `prisma`) не перехватываются — для железобетонной изоляции
  нужен sandbox; здесь это defense-in-depth от случайной утечки в контекст, не барьер.
- `.env.example` (шаблоны, безопасны, полезны) остаётся читаемым — паттерны на имя файла
  `.env`, не на префикс.
- Актуально после того, как в `apps/api/.env` легли реальные Google OAuth креды и `JWT_SECRET`.
- Файл `.claude/settings.json` получил `$schema` для валидации/автокомплита в редакторе.

Проверено вживую: `Read`/`cat` на `apps/api/.env` — заблокированы, на `apps/api/.env.example` —
работают.

## Развели имена skill'а и workflow push-gate (2026-08-31)

Раньше и skill (`.claude/skills/push-gate/`), и workflow (`meta.name` в
`.claude/workflows/push-gate.js`) назывались `push-gate`. Функционально это не ломалось —
skill вызывает workflow программно через `Workflow({ name: ... })`, у этого свой реестр, —
но `/push-gate` в автокомплите молча доставался skill'у (у skill'ов приоритет), а в
`/workflows` и при чтении репозитория два одинаковых имени сбивали с толку: непонятно, кто
вход, а кто движок под ним.

- `meta.name` workflow: `push-gate` → **`push-gate-pipeline`**.
- Файл: `.claude/workflows/push-gate.js` → **`.claude/workflows/push-gate-pipeline.js`**.
- `SKILL.md` Шаг 1: вызов теперь `Workflow({ name: 'push-gate-pipeline', ... })`, добавлена
  явная заметка про разделение ролей (skill = вход для человека, workflow = движок).
- Обновлены ссылки на путь файла в `.claude/agents/{security,frontend,backend}-reviewer.md`,
  `.claude/README.md` (таблица теперь показывает имя каждого компонента), корневом `README.md`.
- Историческая запись ниже (2026-08-27) намеренно оставлена со старым путём `push-gate.js` —
  это фиксация того, что было верно на тот момент.

`/push-gate` (skill) — единственная команда, которую набирает человек; `push-gate-pipeline`
напрямую вызывать не нужно.

## Фикс двух реальных багов в push-gate.js (2026-08-27)

Разбирая механику `push-gate` для объяснения пользователю, нашли и исправили два настоящих
бага в самом оркестраторе (`.claude/workflows/push-gate.js`), не гипотетических:

- **Потеря/подмена находок глубоких ревьюеров**: результаты трёх условных deep-агентов
  (`security-reviewer`/`frontend-reviewer`/`backend-reviewer`) разбирались из массива
  позиционной деструктуризацией (`const [..., deepSecRes, frontendRes, backendRes] = results`),
  а сам массив собирался условно (`if (needsX) tasks.push(...)`) — в частом случае, когда
  задета не вся тройка сразу, результат одного ревьюера тихо попадал в переменную с чужим
  именем (например, находки `frontend-reviewer` записывались в `deepSecRes`), а в самом
  жёстком случае находки терялись целиком (переменная оставалась `undefined`) — фиксер их
  просто никогда не видел. Исправлено: задачи собираются как `{key, run}`, результаты после
  `parallel()` разбираются `Object.fromEntries` по ключу, а не по позиции — порядок/состав
  условных задач больше не важен.
- **`missing-test-writer` потерял независимую проверку качества**: до появления `push-gate`
  этим занимался отдельный `generate-tests.js` по схеме «написать → независимо перепроверить
  ДРУГИМ агентом → починить при отказе» — специально против тестов, написанных «ради
  циферки покрытия» (тавтологичные assert'ы, слишком слабые проверки). При переносе логики
  в `missing-test-writer` внутри `push-gate.js` независимая половина потерялась — агент сам
  писал тест, сам его прогонял и сам себе выдавал «зачёт» (self-grading). Восстановлено:
  новый шаг `test-quality-verifier` — отдельный агент, запускается ПОСЛЕ барьера `parallel()`
  (должен видеть уже написанные на диск файлы), независимо перепрогоняет и оценивает КАЖДЫЙ
  тест-файл в диапазоне (не только новые от `missing-test-writer`, но и правки фиксера на
  следующих итерациях — та же логика «всегда перечитывать живой диф», что у остальных
  ревьюеров конвейера).

## Production-аудит: Tier 0 закрыт целиком + production Docker-образы (2026-08-26)

По итогам полного архитектурного аудита («Blueprint to Production») — реализован весь Tier 0
(критично до первого реального пользователя) плюс production-контейнеризация (изначально
Tier 1, попросили начать раньше очереди):

- **CORS через env** — `ALLOWED_ORIGINS` вместо захардкоженных localhost-адресов в `main.ts`.
- **Graceful shutdown** — `app.enableShutdownHooks()`, реально проверено: `docker stop` даёт
  exit code 0, `PrismaService.onModuleDestroy()` срабатывает.
- **Валидация env на старте** — Joi-схема (`config/env.validation.ts`) через
  `ConfigModule.forRoot({ validate })`. `JWT_SECRET` сознательно не в схеме — им уже
  занимается `jwt-secret.ts` с более полезным сообщением, дублировать не стали. Проверено
  живым негативным тестом: битый `DATABASE_URL` валит приложение сразу с понятной ошибкой.
- **Server-side отзыв JWT** — новая модель `RevokedToken`, `JwtStrategy` проверяет `jti` на
  каждом запросе, `POST /auth/logout` реально отзывает токен (не только чистит
  `localStorage`, как было). Фронтенд: новый хук `useLogout` (TanStack mutation), очищает
  локальный стор в обоих исходах (успех/ошибка запроса) — логаут не должен блокироваться
  сетевым сбоем.
- **Rate limit на создание ссылок** — `POST /links` теперь тоже под `ThrottlerGuard` (жёстче
  дефолта: 10/60с против 30/60с у редиректа) — это была реальная точка злоупотребления
  (спам/фишинг-ссылки), не только сам клик по уже созданной.
- **Production Dockerfile'ы для api и web** — реально собраны и прогнаны вместе на одной
  Docker-сети (веб проксирует `/api/*` на бэкенд по имени сервиса, как в dev через Vite),
  не только написаны на бумаге: статика отдаётся, `/api/health` доходит до настоящей Postgres
  через прокси, graceful shutdown подтверждён живым `docker stop`. По пути нашли и исправили
  реальный баг сборки (не гипотезу) — без корневого `.dockerignore` локальный `node_modules`
  хоста (с symlink'ами на абсолютные хостовые пути) утекал в образ и перекрывал корректно
  установленный внутри контейнера, ломая резолвинг модулей непредсказуемо. Первая гипотеза
  (частичный workspace-контекст ломает peer-резолвинг pnpm) оказалась неверной — проверено
  изолированным тестом, отклонена, не осталась в документации как неподтверждённая.

Все изменения прогнаны по полному циклу: юнит-тесты (65 backend + 39 frontend, целиком
зелёные), type-check и lint по всему монорепо, E2E (включая a11y-сканы) вживую через
`pnpm dev` + реальный Postgres.

## Три архитектурных пробела закрыты: аудит зависимостей, .mcp.json, a11y в E2E (2026-08-26)

По итогам вопроса «чего не хватает проекту как архитектору» — реализованы три пункта:

- **`pnpm audit` в CI** (`ci.yml`, шаг сразу после install) — zero-config аудит зависимостей по npm advisory database, `--audit-level=high`. Заменил изначально предложенный «Semgrep supply-chain» — тот требует логин/токен (платный продукт Semgrep, не просто Docker-образ без аккаунта, как обычный `semgrep scan`), что не вписывается в уже установленный для этого проекта принцип «MCP/тулинг без аккаунта, где возможно». Первый же реальный прогон нашёл настоящую high-severity уязвимость: транзитивная `deepmerge-ts <8.0.0` (stack exhaustion) через `prisma → @prisma/config → deepmerge-ts` (сборочный тулинг Prisma, не рантайм-код — не достижимо непроверенным вводом, но патч тривиален). Исправлено через `pnpm-workspace.yaml`'s `overrides` (не трогая закреплённую версию самого prisma v6) — `pnpm audit` теперь чист, `prisma validate`/тесты/type-check перепроверены после подмены.
- **`.mcp.json` закоммичен** — пять из шести MCP-серверов (Postgres, Context7, Docker, Playwright, GitHub) теперь воспроизводимы на чистом клоне без ручной настройки по таблице. Semgrep НЕ включён — его конфиг требует абсолютный host-путь текущего чекаута (не переносится между машинами), и сам конвейер (`security-reviewer`/`backend-reviewer`) и так вызывает Semgrep напрямую через Docker+Bash, не через его MCP-инструменты — рецепт добавления для тех, кому нужны интерактивные `mcp__semgrep__*`, задокументирован в `CLAUDE.md`. Postgres-креды в файле — не секрет, те же дефолтные dev-значения, что уже открыто в шаблоне `.env` этого же `CLAUDE.md`.
- **a11y-скан в E2E** (`@axe-core/playwright`, `apps/e2e/tests/full-flow.spec.ts`) — на трёх ключевых страницах (`/login`, Dashboard, LinkDetail/analytics), `serious`/`critical` impact only. Объективный, детерминированный второй слой поверх LLM-ревью `frontend-reviewer`, тот же принцип, что `security-reviewer`+Semgrep. Реально прогнано локально (`pnpm dev` + `docker compose` + `playwright test`) — оба теста зелёные, на всех трёх страницах серьёзных нарушений не найдено.

## Ревьюеры расширены до полной базы своего направления (2026-08-26)

Строгий разбор показал, что все три доменных ревьюера покрывали свою область лишь частично:

- **`security-reviewer`** триггерился и читал только auth-пути — никогда не видел
  `apps/api/src/main.ts` (CORS, security-заголовки, `ValidationPipe`) и `apps/api/src/redirect/`
  (единственный эндпоинт без `JwtAuthGuard`, публично доступный кому угодно). Разбор
  реального кода вскрыл два настоящих пробела: в проекте вообще не было `helmet` (ни одного
  security-заголовка ответа) и не было `@nestjs/throttler` — `GET /:code` можно было долбить
  без всякого лимита, каждый вызов пишет строку в `Click`. Скоуп ревьюера расширен на обе
  области (стало 8 категорий вместо 6). Оба пробела исправлены здесь же, тем же заходом:
  добавлен `app.use(helmet(...))` в `main.ts` (CSP отключён вне продакшена — иначе ломает
  Swagger UI) и `ThrottlerModule` в `app.module.ts`, применённый точечно через
  `@UseGuards(ThrottlerGuard)` только на `RedirectController` (30 запросов/60с) — не как
  глобальный guard, чтобы не лимитировать авторизованный dashboard-трафик. Юнит-тест
  `redirect.controller.spec.ts` обновлён — стабит `ThrottlerGuard` через `overrideGuard`,
  не поднимает реальное хранилище throttler'а.
- **`ui-reviewer` → `frontend-reviewer`** — старое имя и скоуп (только a11y + визуал) не
  отражали реальную FE-базу. Добавлены: React-гигиена (зависимости эффектов, cleanup, ключи
  списков, компонент не обходит `apiClient` сырым `fetch`), конвенции TanStack Query (ключ
  запроса — константа/фабрика рядом с хуком, мутация инвалидирует кэш, `isLoading`/`isError`

## commit-gate → push-gate: гейт перенесён с git commit на git push (2026-08-26)

Разобрали ещё раз по цепочке рассуждений с прошлых двух записей: у конвейера была
неверная точка привязки. `git commit` по своей природе должен оставаться дешёвой, частой,
локальной операцией — можно свободно коммитить, `--amend`, `rebase`, экспериментировать
без штрафа. Вешать на КАЖДЫЙ такой коммит полный AI-конвейер значило либо платить его
стоимость много раз за одну и ту же будущую единицу работы, либо (как было до сих пор)
обходить это костылём «коммитить только когда фича готова целиком» — что само по себе
признак неверно выбранной точки привязки. Тяжёлый гейт по весу принадлежит границе, где
код реально покидает машину, — `git push` (та же граница, где стартует CI), не каждому
локальному чекпоинту.

Переименовано и переработано целиком: `commit-gate` → `push-gate` (hook, skill, workflow,
файл-расписка). Ключевые изменения в механике:

- **Два независимых гейта в одном hook-скрипте**: на `git commit` — только быстрый
  `pnpm lint`, без AI (было Gate 1 и раньше, никуда не делось). На `git push` — весь
  тяжёлый конвейер (было раньше на `git commit`).
- **Диапазон диффа сменился**: раньше `git diff --cached` (незакоммиченное). Теперь —
  все локальные коммиты, которых ещё нет на remote: `@{u}..HEAD`, либо merge-base с
  `origin/main` для первого push новой ветки. Диапазон передаётся как символьное
  выражение (не застывший хэш), поэтому автоматически видит новые коммиты, которые
  добавляет фиксер между итерациями.
- **Фиксер теперь коммитит сам** — раньше он просто правил рабочее дерево (коммит делал
  сам skill один раз в самом конце, до того как коммит вообще существовал). Теперь правки
  нужно закоммитить, чтобы они попали в диапазон, который реально уйдёт в push — фиксер
  делает это отдельным коммитом на каждой итерации (`fix: address push-gate findings...`),
  без amend и rebase, история остаётся честной. `missing-test-writer` по-прежнему только
  стейджит (не коммитит) — чтобы два субагента не коммитили одновременно в параллельном
  батче.
- Docs-only быстрый путь перенесён на новый диапазон без изменения логики.

## commit-gate: убрана дублирующая CI регрессия, добавлен backend-reviewer (2026-08-26)

Строгий архитектурный ревью выявил два пробела в конвейере `commit-gate` (см. записи ниже):

  убран целиком.** Он почти один в один дублировал уже существующий CI
  (`.github/workflows/ci.yml`, `e2e.yml`), при этом синхронно блокировал каждый локальный

  2, это осознанный trade-off ради скорости и отсутствия дублирования, не оговаривался
  отдельно как то, что стоило бы оставить.
- **Добавлен `backend-reviewer`** (`.claude/agents/backend-reviewer.md`) — до этого

  никто отдельно — только общий, лёгкий `code-reviewer`. Подключается программно в

## Автоматизация: commit-gate заменяет stage-review (2026-08-25)

Восемь этапов ниже — законченная история; дальше единица работы не «этап», а коммит.
`/stage-review N` (номер этапа, git-теги `stage-N-done`, ручной вызов) полностью заменён
на `commit-gate` — конвейер, висящий прямо на `git commit` через pre-commit hook, без
единой ручной команды:

- **Точка входа** — hook `.claude/hooks/commit-gate.sh` блокирует голый `git commit`,
  пока не появится одноразовая расписка `.claude/.commit-gate-passed` (хэш застейдженного
  диффа) — её пишет сам конвейер прямо перед реальным коммитом. Диапазон ревью больше не
  требует тега: это всегда `git diff --cached` против `HEAD`.
- **Заход 1 (affected)** теперь включает не только code+security ревью диффа, но и тесты,
  затронутые именно этим дифом (Turborepo affected-filter + Jest/Vitest `--changed`), и
  автогенерацию тестов для изменённых файлов без покрытия (логика бывшего
  `generate-tests.js`, теперь встроена как шаг `missing-test-writer`). Если диф трогает
  `auth/` или `apps/web/src` — Заход 1 сам подключает `security-reviewer.md`/
  `ui-reviewer.md` целиком, программно, без ручного вызова.
- **Заход 2 (регрессия)** — integration-ревью всего проекта плюс полный прогон: весь
  `pnpm test`, весь `pnpm --filter e2e test:e2e`, `type-check`, `build` — паритет с тем,
  что CI проверяет на push, только раньше, локально, до коммита.
- **Фиксер больше не коммитит** — на каждой итерации правит рабочее дерево напрямую, весь
  заход перезапускается с нуля. Раньше фиксер делал реальные git-коммиты (до 6 за этап),
  каждый из которых бил по lint-хуку; теперь коммит только один, в самом конце, когда всё
  чисто — сам вопрос «сколько раз лишний прогон» больше не возникает как класс.
- **Удалено**: `.claude/skills/stage-review/`, `.claude/workflows/stage-review.js`,
  `.claude/commands/gen-nest-crud.md` (ни разу не использовался после Этапа 2, все
  реальные модули уже написаны вручную).
