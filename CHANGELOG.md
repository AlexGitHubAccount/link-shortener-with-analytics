# Changelog

Формат по мотивам [Keep a Changelog](https://keepachangelog.com/) — вместо восьми
отдельных `stage-N-*.md`-файлов, по одной записи на этап, в момент его завершения.
Здесь — **что сделано и что пошло не по исходному плану**, один раз, без обязанности
держать в синхроне несколько документов. Актуальный стек, конвенции и известные
грабли — в [`CLAUDE.md`](./CLAUDE.md), не здесь; здесь — история, там — справочник.

Полная детализация по восьми этапам ниже (пошаговые команды, находки `/stage-review` по
итерациям, скриншоты-верификации) осталась в git-истории — каждый этап был зафиксирован
тегом `stage-N-done`, `git show stage-N-done` или `git log` покажет всё, что не попало в
этот сжатый пересказ. С записи «Автоматизация: commit-gate заменяет stage-review» этапы и
теги закончились — дальше запись в этом файле появляется на каждый коммит (единицу
работы), без номера, датой. Датированные записи остаются единицей работы; заголовок
`## [x.y.z]` появляется отдельно, в момент релиза, как якорь версии (semver: MAJOR —
ломающее, MINOR — фича, PATCH — багфикс) с git-тегом `vX.Y.Z` и GitHub Release.

## Команда приведена к форме современной продуктовой: `code-reviewer` + `test-engineer` → один `qa-engineer` (2026-09-02)

Итог серии итераций по составу (три записи ниже — промежуточные состояния одного дня).
Финальная форма — как в живой продуктовой команде сегодня:

- **Разработчики владеют своим кодом целиком, включая юнит-тесты.** `backend-dev` пишет свои
  `*.spec.ts`, `frontend-dev` — свои `*.test.tsx`, каждый держит порог 80% (`test:cov` в
  готовности). «You build it, you test it» — быстрый цикл обратной связи, никто не ждёт
  третьего.
- **`code-reviewer` и `test-engineer` слиты в `qa-engineer`** — инженер по качеству, две
  шляпы по фазам (как QE на малой команде: и ревьюит PR, и держит E2E-набор):
  - *режим ревью* — субагент БЕЗ имени, на КАЖДОМ диапазоне перед push (push-gate Шаг 2,
    feature Шаг 4): корректность, конвенции проекта, явная безопасность, **адекватность
    тестов** (новый путь без теста, тест на старое поведение, пустые утверждения). Промпт
    начинается с «Review mode.». `high` блокирует push.
  - *режим тиммейта* «qa» — спавнится в feature Шаг 2 ТОЛЬКО когда фича добавляет новый
    пользовательский флоу и нужен новый E2E. Владеет `apps/e2e/**` и только им.
- **Состав: 1 + 2 + 2** — лид (архитектор + инфра + релиз) + `backend-dev` + `frontend-dev`
  + `qa-engineer` + `devsecops-reviewer` (без изменений, по условию).

Почему `qa-engineer` — субагент-первично, а тиммейт по случаю: ревью нужно на каждом push
(субагент, read-only, пост-фактум), новый E2E — редко (тиммейт, пишет файлы, во время
разработки). Одно определение, два режима — так же устроены dev-агенты («тиммейт или
субагент»).

Затронуты: `agents/qa-engineer.md` (новый, заменил `code-reviewer.md` + `test-engineer.md` —
оба удалены), `agents/backend-dev.md` / `frontend-dev.md` (вернулось владение юнит-тестами),
`agents/devsecops-reviewer.md`, `skills/push-gate/SKILL.md`, `skills/feature/SKILL.md`,
`.claude/README.md`, `CLAUDE.md`, `README.md`.

## Всё тестирование — в одни руки: `test-engineer` вернулся тиммейтом, единственный владелец всех тестов (2026-09-02)

Финал итерации по составу команды. Предыдущий шаг (ниже) убрал `test-engineer` и раздал
юнит-тесты по dev-агентам («you build it, you test it»). По решению пользователя — свести
всё тестирование к одной роли: проще, одна граница владения, ноль неоднозначности.

**Почему тиммейт, а не субагент** (best practice для этой роли): написание тестов = запись
файлов = зона владения = тиммейт по определению. Субагенты в этом проекте read-only
(`push-gate` — «только отчёт, код не правит»; ревьюеры `feature` Шаг 4 — read-only). Тесты
пишутся во время разработки, параллельно с реализацией — это жизненный цикл тиммейта, не
пост-фактум гейта. Модель выделенного SDET — законная мейнстрим-практика и более простая из
двух (против «каждый тестит своё», где владение тестами размазано).

- **`test-engineer` восстановлен** (`agents/test-engineer.md`) как тиммейт (обычно имя
  `qa`), **единственный** владелец `*.spec.ts` + `*.test.tsx` + `apps/e2e/**`. Jest,
  Vitest+RTL, Playwright-E2E, порог покрытия 80%. Может вызываться и разовым субагентом для
  точечной задачи по тестам.
- **`backend-dev` / `frontend-dev`** — зона сужена до продакшен-кода (без `*.spec.ts` /
  `*.test.tsx`). Секции «Тесты — ваши» убраны; сломанный от смены поведения тест чинит
  `test-engineer` (задача-зависимость), dev-агенты тест-файлы не трогают. Готовность —
  `lint` + `type-check` + `build` (не `test:cov`).
- **`code-reviewer`** получил пункт «Дыра в тестах» — грубо отмечает только совсем
  непокрытый нетривиальный путь, одной находкой `medium`; порог и качество держат
  `test-engineer` + детерминированный `test:cov` в гейте.
- Состав: **1 + 3 + 2** (лид + `backend-dev`/`frontend-dev`/`test-engineer` + `code-reviewer`/
  `devsecops-reviewer`).

Затронуты: `agents/test-engineer.md` (восстановлен), `agents/backend-dev.md` /
`frontend-dev.md` / `code-reviewer.md`, `skills/feature/SKILL.md`, `skills/push-gate/SKILL.md`,
`.claude/README.md`, `CLAUDE.md`, `README.md`.

## Команда упрощена до 1 + 2 + 2: security + devops слиты в один `devsecops-reviewer` (2026-09-02)

Продолжение разбора состава. Предыдущая итерация (запись ниже) вернула `security-reviewer`
и добавила `test-engineer` тиммейтом — по факту вышло избыточно для соло-проекта такого
масштаба. Ужали до минимальной оси с чёткими непересекающимися зонами:

- **`test-engineer` убран как тиммейт.** «You build it, you test it»: `backend-dev` пишет
  свои `*.spec.ts`, `frontend-dev` — свои `*.test.tsx`, каждый держит порог покрытия 80% на
  своём слое (проверяется `test:cov` в `push-gate` и CI). Минус один участник, минус
  зависимость «жду и be, и fe». E2E (`apps/e2e/**`) — кросс-слойное, закрепляется ЯВНО за
  одним тиммейтом в задаче либо делает лид. Оба dev-агента (`agents/backend-dev.md`,
  `frontend-dev.md`) получили секцию «Тесты — ваши» с правилами из бывшего `test-engineer.md`.
- **`security-reviewer` + предложенный отдельный `devops` слиты в `devsecops-reviewer`.**
  Практика DevSecOps: security встроена в тот же путь доставки, что и код — один ревьюер,
  два внутренних прохода, каждый включается только если diff задел его зону:
  - **security-проход** — прежние 8 областей + Semgrep (триггер: `auth/`, `common/guards|
    decorators/`, `main.ts`, `redirect/`, FE `features/auth/` / `auth.store.ts` /
    `api-client.ts`).
  - **devops-проход** — env-переменная во всех местах сразу (Joi-схема + `ci.yml` +
    `.env.example` + Dockerfile), `allowBuilds`/lockfile-синхрон, `dependsOn: ["^build"]`
    для новых turbo-задач, Docker-контекст/`.dockerignore`, CI-обвязка, `pnpm audit`
    (триггер: `.github/workflows/`, `Dockerfile*`, `nginx.conf.template`, `docker-compose.yml`,
    `turbo.json`, `.dockerignore`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, любой
    `package.json`, `config/env.validation.ts`).

  Находки помечаются `[security]`/`[devops]`; `high` от любого прохода блокирует push, при
  `[security] high` рекомендуется `/code-review ultra`. Это по-прежнему субагент **без
  имени** (не тиммейт), схема вывода не изменилась.
- **Роль архитектора/DevOps остаётся на лиде.** Инфра-файлы правит лид напрямую (редкие,
  кросс-слойные), `devsecops-reviewer` их проверяет. `feature/SKILL.md` Шаг 1.2 получил
  пункт «Инфра / путь в прод» и требование выдавать одну строку threat-модели на
  auth-фичах.

Затронуты: `agents/devsecops-reviewer.md` (новый, заменил `security-reviewer.md`),
`agents/test-engineer.md` (удалён), `agents/backend-dev.md` / `frontend-dev.md` (секция

## [1.0.0] — 2026-09-01

Первый готовый к выпуску срез. Все 8 запланированных этапов закрыты, плюс post-Stage-8
production-подготовка (Tier 0) и переработка тулинга. `main` на GitHub, CI зелёный
(`lint-type-test-build` + `e2e`), тег `v1.0.0`.

**Что входит:**

- **Backend** (NestJS + Prisma + PostgreSQL): CRUD ссылок, публичный редирект `GET /:code`
  с fire-and-forget записью клика, аналитика (`GET /links/:id/analytics` — агрегация в SQL,
  парсинг User-Agent), Google OAuth + JWT со server-side отзывом токена (`RevokedToken`),
  скоупинг всех приватных эндпоинтов по `@CurrentUser()`, Swagger `/api/docs` (отключён в
  проде). Tier 0 hardening: `helmet`, CORS через `ALLOWED_ORIGINS`, `ThrottlerGuard` на
  публичных путях, Joi-валидация env на старте, graceful shutdown.
- **Frontend** (Vite + React 19 + TanStack Query + shadcn/ui + Tailwind v4): Dashboard,
  создание ссылки (react-hook-form + zod), список, страница аналитики с графиками (recharts),
  server-side логаут.
- **Инфраструктура**: pnpm workspace + Turborepo, dev-Postgres в docker-compose,
  production-образы `apps/api/Dockerfile` + `apps/web/Dockerfile` (собраны и прогнаны в
  связке), GitHub Actions CI (`lint · type-check · test:cov 80% · build · pnpm audit`, затем
  `e2e` с Playwright + `@axe-core` a11y-сканом), детерминированный `push-gate` (гейт-зеркало
  CI перед push), команда разработки на Agent Teams (`/feature`).
- **Тесты**: Jest (api) + Vitest/RTL (web) + Playwright (e2e), покрытие ≥80% по всем 4
  метрикам.

**Известные ограничения 1.0.0:**

- **CD не настроен** — реального деплоя куда-либо нет; выбор платформы (Fly.io/Railway/VPS)
  и разворачивание — за пользователем. CI пока только проверяет, не деплоит.
- Google OAuth требует реальных кредов из Google Cloud Console (в дефолтном `.env` их нет —
  всё, кроме кнопки «Sign in with Google», работает без них).
- Branch protection на `main` сознательно не включён — соло-репозиторий, `push-gate` +
  прямой push (см. `CHANGELOG` ниже про обсуждение).

Полная детализация — в датированных записях ниже (они и есть история пути к 1.0.0).

## CI покраснел на пороге покрытия сразу после первого push — починка + закрытие дыры в гейте (2026-09-01)

Первый прогон `ci.yml` на GitHub упал: `test:cov` → branch coverage 79.9% при пороге 80%
(`jest.coverageThreshold`). Детерминированный `quality-checks.sh` этого не поймал, потому
что гонял `turbo run test`, а НЕ `test:cov` — порог покрытия в голом `test` не проверяется.

- **Причина просадки**: правка advisory-находки (`5e354f6`) убрала ветку `$transaction` в
  `analytics.service`, а коммиты переработки `.claude/` (`1cc4d6e`) добавили пару мелких
  веток в `main.ts`/`links.service.ts`/`redirect.controller.ts` без тестов — суммарно
  branch coverage сполз с ~80.6% до 79.9%.
- **Починка**: три реальных теста на непокрытые ветки `AuthController.logout` (токен без
  `exp` → `expiresAt` = now + 24ч; падение ленивой очистки `RevokedToken` → логаут всё
  равно успешен, пишется warning). Branch coverage → 80.86%.
- **Закрытие дыры**: `quality-checks.sh` теперь гоняет `test:cov`, а не `test` — гейт
  enforce'ит ровно тот порог, что и CI. Обновлён и `skills/push-gate/SKILL.md`.

## Первый push всей post-Stage-8 работы на remote (2026-09-01)

Вся работа после Этапа 8 (Tier 0, production Docker, слияние CI, рефактор `.claude/`,
консолидация доков, переписанный детерминированный push-gate) до этого момента лежала
только в рабочем дереве — `origin/main` оставался на `3f87325` (Этап 8). Собрано в 13
коммитов и отправлено на GitHub одним push после чистого прогона детерминированного гейта
(`quality-checks.sh`: lint · affected type-check/test/build · скан секретов — всё зелёное).

Advisory-проход `code-reviewer` нашёл два хвоста от автономного фиксера прежнего
`push-gate-pipeline.js` (см. запись ниже — фиксер был удалён именно за такое):

- **`analytics.service.getLinkAnalytics`** — фиксер обернул четыре параллельных чтения в
  интерактивный `$transaction((tx) => Promise.all([...]))`. Параллельные запросы на одном
  соединении транзакции — антипаттерн Prisma (перемежающиеся ошибки под нагрузкой), а
  READ COMMITTED (дефолт PostgreSQL) всё равно даёт каждому запросу свой снапшот — никакой
  консистентности транзакция не покупала. Откат к обычному `Promise.all`; полезную часть
  правки фиксера (агрегация по дням в SQL через `GROUP BY` вместо загрузки всех строк
  `Click` в Node) оставили.
- **`JwtPayload.jti` / `RequestUser.jti`** были типизированы как обязательные `string`, хотя
  токены, выпущенные до фичи отзыва, поля не имеют. Рантайм и так это обрабатывал
  (`if (payload.jti)` / `if (!jti)`), тип просто врал → `jti?: string`.

`code-review` порог `high` — 0 находок, push прошёл.

## push-gate переписан на детерминированный гейт + команда разработки на Agent Teams (2026-08-31)

**Проблема.** `.claude/workflows/push-gate-pipeline.js` на каждой итерации запускал до 9
агентов параллельно (code/security-ревью, affected-тесты, автогенерация недостающих тестов,
3 глубоких ревьюера, test-quality-verifier, fixer) и крутил цикл до 15 итераций с
**автономным фиксером**, который сам правил код и коммитил. На бумаге «ограничено», на
практике — нет. Реальный прогон: 4 коммита `fix: address push-gate findings (iteration 1-4)`,
фиксер трогал `main.ts` в итерациях 1, 2 и 4 (осцилляция между правками), автономно добавил
Prisma-миграцию и throttler-guard, так и не сошёлся, агенты зависли и съели весь контекст —
сессию пришлось убить вручную.

**Решение — гейт стал детерминированным, предсказуемым и только-отчётным:**

- **Удалён** `.claude/workflows/push-gate-pipeline.js` (и каталог `workflows/`). Нет цикла
  автопочинки, нет автономных коммитов, нет спавна множества агентов, нет автогенерации
  тестов.
- **Новый** `.claude/hooks/quality-checks.sh` — один полный проход, никогда не обрывается на
  первой красной: `pnpm lint` · affected `type-check` · affected `test` (turbo
  `--filter="...[<base>]"`, синтаксис сверен с turbo docs) · affected `build` · скан
  секретов по добавленным строкам диапазона (regex, без внешних зависимостей; `.env.example`
  и `*.md` исключены). Вывод — `CHECK <name> PASS/FAIL` + хвосты логов красных + `GATE
  PASS/FAIL`.
- **Переписан** `skills/push-gate/SKILL.md`: диапазон → `quality-checks.sh` → ОДИН фоновый
  advisory-субагент `code-reviewer` (без имени — чтобы при включённых Agent Teams остался
  субагентом) → единый подробный отчёт человеку → при `GATE PASS` и без `high`-находок:
  doc-sync + расписка + `git push`; иначе — стоп, находки чиним вместе с пользователем
  обычными Edit/Bash, затем повторный `/push-gate`. Docs-only быстрый путь и механизм
  хэш-расписки сохранены.
- **Новый** `agents/code-reviewer.md` — лёгкое diff-scoped ревью (корректность + явная
  безопасность + конвенции), `maxTurns: 12`, только отчёт по схеме, ≤10 находок. Это
  единственный ревьюер в проекте.
- **Удалены** `agents/security-reviewer.md`, `backend-reviewer.md`, `frontend-reviewer.md` —

## Фикс двух реальных багов в push-gate.js (2026-08-27)

Разбирая механику `push-gate` для объяснения пользователю, нашли и исправили два настоящих
бага в самом оркестраторе (`.claude/workflows/push-gate.js`), не гипотетических:

- **Потеря/подмена находок глубоких ревьюеров**: результаты трёх условных deep-агентов
  (`security-reviewer`/`frontend-reviewer`/`backend-reviewer`) разбирались из массива
  позиционной деструктуризацией (`const [..., deepSecRes, frontendRes, backendRes] = results`),
  а сам массив собирался условно (`if (needsX) tasks.push(...)`) — в частом случае, когда
  задета не вся тройка сразу, результат одного ревьюера тихо попадал в переменную с чужим
  именем (например, находки `frontend-reviewer` записывались в `deepSecRes`), а в самом
  жёстком случае находки терялись целиком (переменная оставалась `undefined`) — фиксер их
  просто никогда не видел. Исправлено: задачи собираются как `{key, run}`, результаты после
  `parallel()` разбираются `Object.fromEntries` по ключу, а не по позиции — порядок/состав
  условных задач больше не важен.
- **`missing-test-writer` потерял независимую проверку качества**: до появления `push-gate`
  этим занимался отдельный `generate-tests.js` по схеме «написать → независимо перепроверить
  ДРУГИМ агентом → починить при отказе» — специально против тестов, написанных «ради
  циферки покрытия» (тавтологичные assert'ы, слишком слабые проверки). При переносе логики
  в `missing-test-writer` внутри `push-gate.js` независимая половина потерялась — агент сам
  писал тест, сам его прогонял и сам себе выдавал «зачёт» (self-grading). Восстановлено:
  новый шаг `test-quality-verifier` — отдельный агент, запускается ПОСЛЕ барьера `parallel()`
  (должен видеть уже написанные на диск файлы), независимо перепрогоняет и оценивает КАЖДЫЙ
  тест-файл в диапазоне (не только новые от `missing-test-writer`, но и правки фиксера на
  следующих итерациях — та же логика «всегда перечитывать живой диф», что у остальных
  ревьюеров конвейера).

## Production-аудит: Tier 0 закрыт целиком + production Docker-образы (2026-08-26)

По итогам полного архитектурного аудита («Blueprint to Production») — реализован весь Tier 0
(критично до первого реального пользователя) плюс production-контейнеризация (изначально
Tier 1, попросили начать раньше очереди):

- **CORS через env** — `ALLOWED_ORIGINS` вместо захардкоженных localhost-адресов в `main.ts`.
- **Graceful shutdown** — `app.enableShutdownHooks()`, реально проверено: `docker stop` даёт
  exit code 0, `PrismaService.onModuleDestroy()` срабатывает.
- **Валидация env на старте** — Joi-схема (`config/env.validation.ts`) через
  `ConfigModule.forRoot({ validate })`. `JWT_SECRET` сознательно не в схеме — им уже
  занимается `jwt-secret.ts` с более полезным сообщением, дублировать не стали. Проверено
  живым негативным тестом: битый `DATABASE_URL` валит приложение сразу с понятной ошибкой.
- **Server-side отзыв JWT** — новая модель `RevokedToken`, `JwtStrategy` проверяет `jti` на
  каждом запросе, `POST /auth/logout` реально отзывает токен (не только чистит
  `localStorage`, как было). Фронтенд: новый хук `useLogout` (TanStack mutation), очищает
  локальный стор в обоих исходах (успех/ошибка запроса) — логаут не должен блокироваться
  сетевым сбоем.
- **Rate limit на создание ссылок** — `POST /links` теперь тоже под `ThrottlerGuard` (жёстче
  дефолта: 10/60с против 30/60с у редиректа) — это была реальная точка злоупотребления
  (спам/фишинг-ссылки), не только сам клик по уже созданной.
- **Production Dockerfile'ы для api и web** — реально собраны и прогнаны вместе на одной
  Docker-сети (веб проксирует `/api/*` на бэкенд по имени сервиса, как в dev через Vite),
  не только написаны на бумаге: статика отдаётся, `/api/health` доходит до настоящей Postgres
  через прокси, graceful shutdown подтверждён живым `docker stop`. По пути нашли и исправили
  реальный баг сборки (не гипотезу) — без корневого `.dockerignore` локальный `node_modules`
  хоста (с symlink'ами на абсолютные хостовые пути) утекал в образ и перекрывал корректно
  установленный внутри контейнера, ломая резолвинг модулей непредсказуемо. Первая гипотеза
  (частичный workspace-контекст ломает peer-резолвинг pnpm) оказалась неверной — проверено
  изолированным тестом, отклонена, не осталась в документации как неподтверждённая.

Все изменения прогнаны по полному циклу: юнит-тесты (65 backend + 39 frontend, целиком
зелёные), type-check и lint по всему монорепо, E2E (включая a11y-сканы) вживую через
`pnpm dev` + реальный Postgres.

## commit-gate → push-gate: гейт перенесён с git commit на git push (2026-08-26)

Разобрали ещё раз по цепочке рассуждений с прошлых двух записей: у конвейера была
неверная точка привязки. `git commit` по своей природе должен оставаться дешёвой, частой,
локальной операцией — можно свободно коммитить, `--amend`, `rebase`, экспериментировать
без штрафа. Вешать на КАЖДЫЙ такой коммит полный AI-конвейер значило либо платить его
стоимость много раз за одну и ту же будущую единицу работы, либо (как было до сих пор)
обходить это костылём «коммитить только когда фича готова целиком» — что само по себе
признак неверно выбранной точки привязки. Тяжёлый гейт по весу принадлежит границе, где
код реально покидает машину, — `git push` (та же граница, где стартует CI), не каждому
локальному чекпоинту.

Переименовано и переработано целиком: `commit-gate` → `push-gate` (hook, skill, workflow,
файл-расписка). Ключевые изменения в механике:

- **Два независимых гейта в одном hook-скрипте**: на `git commit` — только быстрый
  `pnpm lint`, без AI (было Gate 1 и раньше, никуда не делось). На `git push` — весь
  тяжёлый конвейер (было раньше на `git commit`).
- **Диапазон диффа сменился**: раньше `git diff --cached` (незакоммиченное). Теперь —
  все локальные коммиты, которых ещё нет на remote: `@{u}..HEAD`, либо merge-base с
  `origin/main` для первого push новой ветки. Диапазон передаётся как символьное
  выражение (не застывший хэш), поэтому автоматически видит новые коммиты, которые
  добавляет фиксер между итерациями.
- **Фиксер теперь коммитит сам** — раньше он просто правил рабочее дерево (коммит делал
  сам skill один раз в самом конце, до того как коммит вообще существовал). Теперь правки
  нужно закоммитить, чтобы они попали в диапазон, который реально уйдёт в push — фиксер
  делает это отдельным коммитом на каждой итерации (`fix: address push-gate findings...`),
  без amend и rebase, история остаётся честной. `missing-test-writer` по-прежнему только
  стейджит (не коммитит) — чтобы два субагента не коммитили одновременно в параллельном
  батче.
- Docs-only быстрый путь перенесён на новый диапазон без изменения логики.

## CI: e2e.yml слит в ci.yml, commit-gate получил docs-only быстрый путь (2026-08-26)

Строгий ревью CI-настройки и всего цикла commit-gate выявил ещё два улучшения:

- **`e2e.yml` слит в `ci.yml`** — раньше это были два независимых workflow, запускавшихся
  параллельно на каждый push/PR: если ломался банальный `lint` в `ci.yml`, `e2e.yml` всё
  равно поднимал Postgres, ставил браузер Playwright и гонял весь E2E — впустую тратил
  CI-минуты на заведомо красный PR. Теперь один файл `ci.yml`, job `e2e` стартует через
  `needs: lint-type-test-build` только после того, как базовые проверки зелёные. README
  лишился отдельного бейджа E2E (статус теперь виден одним CI-бейджем).
- **Заодно исправлены три висячие ссылки** на удалённые ранее `docs/stage-4-authentication.md`/
  `docs/stage-6-testing-qa.md` (в `e2e.yml`-комментарии и дважды в `apps/e2e/tests/auth-helper.ts`)
  — пропустил их при прошлой чистке `docs/`, теперь указывают на `CLAUDE.md`.
- **`commit-gate` получил docs-only быстрый путь** — если весь застейдженный диф состоит

## commit-gate: убрана дублирующая CI регрессия, добавлен backend-reviewer (2026-08-26)

Строгий архитектурный ревью выявил два пробела в конвейере `commit-gate` (см. записи ниже):

- **Заход 2 (integration-ревью + полная регрессия: весь `pnpm test`, весь E2E, `build`)
  убран целиком.** Он почти один в один дублировал уже существующий CI
  (`.github/workflows/ci.yml`, `e2e.yml`), при этом синхронно блокировал каждый локальный
  `git commit` подъёмом Docker и dev-сервера внутри git-хука — стандартная практика (husky/
  lint-staged и т.п.) держит на pre-commit только быстрые точечные проверки, а полную
  регрессию — на CI/pre-push. `commit-gate` теперь состоит из одного захода: диф +
  affected-тесты. Полную регрессию перед мержем гоняет CI после push; вручную локально —
  `pnpm test && pnpm --filter e2e test:e2e && pnpm build` напрямую, вне этого skill'а.
  Известный побочный эффект: integration-ревью «всего проекта разом» (сверка контрактов
  между модулями, которую CI не делает — это AI-ревью, не тесты) тоже ушло вместе с заходом
  2, это осознанный trade-off ради скорости и отсутствия дублирования, не оговаривался
  отдельно как то, что стоило бы оставить.
- **Добавлен `backend-reviewer`** (`.claude/agents/backend-reviewer.md`) — до этого
  `security-reviewer` покрывал только auth, `ui-reviewer` только frontend/a11y, а
  NestJS-паттерны (DI, DTO-валидация) и Prisma/БД-специфика (безопасность миграций, N+1,
  отсутствующие индексы, неограниченные выборки, транзакционная корректность) не проверял
  никто отдельно — только общий, лёгкий `code-reviewer`. Подключается программно в
  `commit-gate.js`, когда диф трогает `apps/api/src` или `apps/api/prisma`, тем же
  паттерном, что и два существующих доменных ревьюера.

Заодно удалена пустая `.claude/commands/` — последний файл в ней (`gen-nest-crud.md`) был
убран раньше, папка держала пустое место без функции.

## Автоматизация: commit-gate заменяет stage-review (2026-08-25)

Восемь этапов ниже — законченная история; дальше единица работы не «этап», а коммит.
`/stage-review N` (номер этапа, git-теги `stage-N-done`, ручной вызов) полностью заменён
на `commit-gate` — конвейер, висящий прямо на `git commit` через pre-commit hook, без
единой ручной команды:

- **Точка входа** — hook `.claude/hooks/commit-gate.sh` блокирует голый `git commit`,
  пока не появится одноразовая расписка `.claude/.commit-gate-passed` (хэш застейдженного
  диффа) — её пишет сам конвейер прямо перед реальным коммитом. Диапазон ревью больше не
  требует тега: это всегда `git diff --cached` против `HEAD`.
- **Заход 1 (affected)** теперь включает не только code+security ревью диффа, но и тесты,
  затронутые именно этим дифом (Turborepo affected-filter + Jest/Vitest `--changed`), и
  автогенерацию тестов для изменённых файлов без покрытия (логика бывшего
  `generate-tests.js`, теперь встроена как шаг `missing-test-writer`). Если диф трогает
  `auth/` или `apps/web/src` — Заход 1 сам подключает `security-reviewer.md`/
  `ui-reviewer.md` целиком, программно, без ручного вызова.
- **Заход 2 (регрессия)** — integration-ревью всего проекта плюс полный прогон: весь
  `pnpm test`, весь `pnpm --filter e2e test:e2e`, `type-check`, `build` — паритет с тем,
  что CI проверяет на push, только раньше, локально, до коммита.
- **Фиксер больше не коммитит** — на каждой итерации правит рабочее дерево напрямую, весь
  заход перезапускается с нуля. Раньше фиксер делал реальные git-коммиты (до 6 за этап),
  каждый из которых бил по lint-хуку; теперь коммит только один, в самом конце, когда всё
  чисто — сам вопрос «сколько раз лишний прогон» больше не возникает как класс.
- **Удалено**: `.claude/skills/stage-review/`, `.claude/workflows/stage-review.js`,
  `.claude/commands/gen-nest-crud.md` (ни разу не использовался после Этапа 2, все
  реальные модули уже написаны вручную).
