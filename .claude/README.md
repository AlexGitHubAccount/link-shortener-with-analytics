# `.claude/` — что здесь лежит и когда срабатывает

Всё, кроме hook'а, срабатывает автоматически по факту события (попытка `git push`, и
отдельно — быстрый lint-гейт на `git commit`) — никакие команды вызывать вручную не нужно.
Вручную можно вызвать `/push-gate`, если хочется проверить текущие неотправленные коммиты
до того как решите пушить.

| Файл | Тип | Когда срабатывает | Что делает |
|---|---|---|---|
| `settings.json` | конфиг | всегда | (1) Регистрирует hook ниже на событие `PreToolUse` (перед каждым Bash-вызовом). (2) `permissions.deny` — Claude не читает `.env`/`.env.local`/`.env.*.local` (реальные секреты: `DATABASE_URL`, `JWT_SECRET`, `GOOGLE_CLIENT_SECRET`); `.env.example` остаётся читаемым. Это официальный аналог `.claudeignore` (самого файла в Claude Code нет, а `ignorePatterns` устарел). Зеркалит `.gitignore`. |
| `hooks/push-gate.sh` | hook | автоматически, реагирует на `git commit` и на `git push` отдельно | Два независимых гейта по весу: (1) на `git commit` — только быстрый `pnpm lint`, без AI, коммитить можно свободно и часто; (2) на `git push` — прошёл ли именно этот диапазон коммитов (`@{u}..HEAD`, или merge-base с `origin/main` для первого push новой ветки) полный конвейер — проверяет одноразовую расписку `.claude/.push-gate-passed` (хэш этого диапазона). Нет расписки → push блокируется, отказ говорит вызвать skill ниже. |
| `skills/push-gate/SKILL.md` | skill, имя `push-gate` | сам, когда hook отклонил push (или вручную `/push-gate`) | Оркестратор: определяет диапазон коммитов и аргументы (нужен ли глубокий auth/frontend/backend-чек), запускает Workflow, при чистом результате сам делает реальный push. **Точка входа для человека** — `/push-gate` в автокомплите это он (у skill'ов приоритет). |
| `workflows/push-gate-pipeline.js` | Workflow, имя `push-gate-pipeline` | запускается из skill'а выше через `Workflow({ name: 'push-gate-pipeline' })` | Диапазон + code/security-ревью + affected-тесты + дозапись недостающих тестов + **независимая** переверка качества каждого тест-файла в диапазоне отдельным агентом (не self-report — ловит тавтологичные/бессмысленные тесты). Фиксер коммитит свои правки отдельным коммитом (не amend, не rebase), конвейер перезапускается с нуля — диапазон авторасширяется вместе с `HEAD`. Полная регрессия (весь тест-сьют, E2E, build) сюда намеренно не входит — это работа CI, дублировать её локально на каждый push — лишняя стоимость и время. Изолированный контекст — не засоряет основную сессию. |
| `agents/security-reviewer.md` | agent-определение | вызывается **программно** из Workflow (если диапазон трогает auth, `main.ts` или `redirect/`) | Глубокий аудит ВСЕЙ security-поверхности: auth + CORS/security-заголовки/ValidationPipe + единственный публичный незащищённый эндпоинт + Semgrep. Больше не вызывается вами вручную — конвейер сам решает, когда он нужен. |
| `agents/frontend-reviewer.md` | agent-определение | вызывается **программно** из Workflow (если диапазон трогает `apps/web/src`) | a11y + визуальная консистентность + React-гигиена (эффекты, ключи списков) + TanStack Query конвенции (ключи, инвалидация, состояния загрузки/ошибки) + UX форм/роутинга. Раньше назывался `ui-reviewer` — переименован вместе с расширением скоупа, старое имя не отражало реальный охват. |
| `agents/backend-reviewer.md` | agent-определение | вызывается **программно** из Workflow (если диапазон трогает `apps/api/src` или `apps/api/prisma`) | NestJS-паттерны + корректность/целостность Prisma/БД (миграции, N+1, индексы, транзакции) + Swagger/DTO-консистентность — не security, для этого отдельный `security-reviewer`. |

Подробнее про сам процесс — в `skills/push-gate/SKILL.md` (источник истины, не
пересказывается больше нигде). Датированная история того, как эта таблица дошла до
нынешнего вида (что было раньше, что и почему поменялось) — в `../CHANGELOG.md`, не здесь:
эта страница — карта текущего состояния, не журнал изменений. Про стек и конвенции —
в `../CLAUDE.md`.
