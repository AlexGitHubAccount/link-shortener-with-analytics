# stage-review

Все ревью-рассуждения выполняются в изолированных агентских контекстах через `Workflow({name: 'stage-review', ...})` — это не засоряет контекст основной сессии. Этот skill только подготавливает аргументы, запускает workflow и обрабатывает итоговый результат (тег, статусы в доках, сводка пользователю).

## Аргумент

Номер этапа (например `2`). Если не передан — спросить пользователя явно.

## Шаг 0: контекст и подготовка аргументов

1. Прочитать `docs/stage-N-*.md` для этого номера — что этап должен был дать по плану, критерии верификации из раздела «Верификация».
2. Проверить `git tag -l`:
   - **N=1**: `skipPass1 = true` (нечего диффить от несуществующего `stage-0-done`).
   - **N>1, тег `stage-(N-1)-done` существует**: `skipPass1 = false`, `diffRange = "stage-(N-1)-done"`.
   - **N>1, тега нет**: сообщить пользователю и остановиться — без базовой точки Заход 1 невозможен.
3. `scanPaths = "apps/api/src apps/web/src packages/"` (полные пути целиком, для Захода 2).

## Шаг 1: запуск workflow

Вызвать `Workflow({ name: 'stage-review', args: { diffRange, scanPaths, skipPass1 } })` и дождаться результата. Это запустит workflow-скрипт (`.claude/workflows/stage-review.js`), который:
- В своём собственном контексте (не в основной сессии) запустит Заход 1 (если `skipPass1 === false`): параллельно code-reviewer + security-reviewer на `git diff ${diffRange}`, затем fixer-цикл до чистого состояния или истечения макс. 3 итераций.
- Если Заход 1 чист, то Заход 2: integration-reviewer на полном скане `scanPaths`, затем fixer-цикл (макс. 3 итерации).
- Вернёт структурированный результат: `{ status: 'clean' | 'pass1-dirty' | 'pass2-dirty', pass1: {...}, pass2: {...} }`.

## Шаг 2: обработка результата

- **`status === 'clean'`**:
  1. `git tag stage-N-done` на текущем HEAD.
  2. Отметить ✅ в `docs/stage-N-*.md` (статус этапа).
  3. Обновить таблицу «Роадмап по этапам» в `docs/plan.md` (строка для Этапа N).
  4. Дать пользователю сводку: сколько итераций ушло на Заход 1 и Заход 2, финальный вердикт — этап завершён.

- **`status === 'pass1-dirty' | 'pass2-dirty'`**:
  1. НЕ тегировать, НЕ отмечать ✅.
  2. Показать пользователю `result.pass1.findings` / `result.pass2.findings` — неразрешённые находки.
  3. Предложить варианты: (а) самостоятельно разобраться с находками, затем запустить `/stage-review N` снова; (б) предложить эскалацию `/code-review ultra` для чувствительных этапов (например, Этап 4).

## Опциональная эскалация

Для особо чувствительных этапов (явный кандидат — Этап 4, авторизация) пользователь может самостоятельно запустить `/code-review ultra` — глубокое многоагентное облачное ревью. Платно, должно быть инициировано пользователем напрямую в чате. Этот skill не запускает `ultra` автоматически.
