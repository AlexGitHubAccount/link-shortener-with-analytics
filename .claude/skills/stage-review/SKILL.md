# stage-review

Прогоняет для этапа `docs/stage-N-*.md` два последовательных захода ревью с расширением скоупа. Не хардкодит поиск багов сам — вызывает встроенные skills `code-review` и `security-review` с правильным скоупом и уровнем строгости на каждом заходе.

## Аргумент

Номер этапа (например `2`). Если не передан — спросить пользователя явно, для какого этапа запускать ревью, не гадать.

## Шаг 0: контекст

1. Прочитать `docs/stage-N-*.md` для этого номера — что этап должен был дать по плану, критерии верификации из раздела «Верификация».
2. Проверить, что тег `stage-(N-1)-done` существует (`git tag -l`) — это база для Захода 1. Если предыдущего тега нет **и N > 1** — сообщить пользователю и остановиться: без базовой точки Заход 1 не имеет смысла. **Особый случай N=1**: предыдущего тега не существует по определению (первый этап, диффить не с чем) — Заход 1 в этом случае пропускается, сразу выполняется только Заход 2 (весь код), т.к. для первого этапа «только новый этап» и «весь накопленный код» — это одно и то же.

## Заход 1 — только новый этап (узкий скоуп)

Скоуп: `git diff stage-(N-1)-done..HEAD`.

1. Запустить skill `code-review` на этом диффе, уровень строгости `medium`.
2. Запустить skill `security-review` на том же диффе.
3. Если есть находки — кратко объяснить пользователю, что нашли и почему это проблема, исправить, затем повторить шаги 1–2 на обновлённом диффе.
4. Максимум 3 итерации. Если после 3-й итерации всё ещё есть находки — остановиться, показать оставшиеся находки пользователю, **не переходить к Заходу 2 самостоятельно**.
5. Как только чисто — явно сообщить: «Заход 1 (скоуп: только Этап N) — чисто» и перейти к Заходу 2.

## Заход 2 — весь накопленный код (широкий скоуп)

Скоуп: пути `apps/api/src apps/web/src packages/` целиком (не дифф, а полное сканирование всего текущего кода проекта — ловит интеграционные проблемы между этапами, которые не видны в узком диффе Захода 1).

1. Запустить skill `code-review` на этом скоупе, уровень строгости `medium`.
2. Запустить skill `security-review` на том же скоупе.
3. Тот же цикл «нашли → почини → перепроверь», максимум 3 итерации.
4. Как только чисто — явно сообщить: «Заход 2 (весь проект) — чисто».

## Завершение

1. `git tag stage-N-done` на текущем HEAD.
2. Обновить статус этапа на ✅ в `docs/stage-N-*.md` и в таблице «Роадмап по этапам» в `docs/plan.md`.
3. Дать пользователю связную сводку: что искали на каждом заходе, что нашли, что починили, финальный вердикт.

## Опциональная эскалация

Для особо чувствительных этапов (явный кандидат — Этап 4, авторизация) пользователь может сам явно запустить `/code-review ultra` — глубокое многоагентное облачное ревью с перекрёстной проверкой находок между независимыми агентами. Это платно и должно быть инициировано пользователем напрямую в чате — этот skill не запускает `ultra` самостоятельно.
